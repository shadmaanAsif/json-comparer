Status: Recommendation as of 2026-08-21. Resolve versions at implementation time, commit the lockfile, and pin production to supported patched releases rather than copying version numbers from this plan.

## 2. Dependency principles

- Start with the baseline packages only. Conditional packages are not installed until their feature is approved.
- Prefer platform and framework capabilities: Web Worker, File API, Blob download, native fetch, `AbortController`, React reducer, Next.js headers/env.
- Use exact resolved versions in the lockfile, automated update PRs, supported majors, license review, vulnerability scanning, and scheduled removal of unused dependencies.
- Do not use a general JSON-diff package for the domain core. The required ordered/unordered modes, separate source paths, schema findings, ignore semantics, cancellation, limits, and stable IDs form product-specific behavior that needs explicit ownership.
- Do not add Axios (native fetch suffices), Lodash (language primitives suffice), Redux/Zustand initially, TanStack Query without server CRUD, a cURL parser until supported syntax is specified, or a full editor before profiling.

## 6. Version and maintenance policy

- Node: current Active LTS approved by Next.js at implementation start; record it in `engines` and `.nvmrc`/tool manager.
- Next.js: use the current patched Active LTS, not an unpatched minor. As of the research date, Next.js announced 16.2.11 as Active LTS and 16.3 as the newer line; verify security advisories immediately before scaffolding ([Next.js blog](https://nextjs.org/blog)).
- React: version compatible with selected Next.js; do not independently force a mismatched version.
- Package manager: pinned pnpm major through `packageManager`; `pnpm install --frozen-lockfile` in CI.
- Renovate or Dependabot: weekly grouped non-breaking updates, immediate security updates, manual major upgrades with migration notes.
- Every dependency needs a named owner, license approval, usage in source, and removal when unused. Quarterly dependency audit includes maintenance activity, release/security history, bundle/runtime cost, and replacement risk.

## 7. Technology spikes before commitment

1. Benchmark worker parse/diff and message-copy cost at 1/5/10 MB with deeply nested and large unordered arrays.
2. Compare native textarea/tree against CodeMirror and virtualization for accessibility, navigation accuracy, bundle size, and responsiveness.
3. Prove the chosen hosting/network path can block private destinations and revalidate redirects for remote import; otherwise use hostname allowlisting or omit the feature.
4. Confirm Tailwind v4 browser floor against the target browser matrix.
5. If P2 is approved, compare Prisma with Drizzle/Kysely on expected query patterns and verify Auth.js/IdP session and authorization requirements.
